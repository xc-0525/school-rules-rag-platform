## 三、"文献调研"栏正文（按上表编号，约 620 字）

国内研究方面，校园与高校问答系统正从关键词检索转向"检索 + 生成"的融合架构。卞佳兴[9]面向高校规章制度提出"BM25 + 向量语义"混合检索、证据覆盖排序与置信拒答方法，基于 35 份公开制度构建知识库，综合正确率达 96.9%，其"低于阈值即拒答并返回制度条目"的思路对本课题最具借鉴价值；王克勤等[5]将 Graph-RAG 用于考古学文化问答，验证了图谱关系扩展对专业领域问答的增益；袁乐等[10]以"索引—检索—生成"为主线梳理了 RAG 的六类优化方向，为本系统的检索链路设计提供了框架参照。可信性方面，刘泽垣等[7]系统归纳了大模型幻觉的成因、分类与评估方法，赵月等[8]从安全视角讨论了模型输出的不可控风险，二者共同支撑了"证据约束 + 引用校验 + 拒答"的设计动机。

国外研究方面，Alexandrou 等[11]在急性冠脉综合征指南问答上验证了 RAG 的增益：ChatGPT-4o 准确率由 71.1% 提升至 92.1%，DeepSeek R1 结合 RAG 达 94.7%，说明"条款型知识 + 检索增强"能显著降低事实性错误，这与校规条款问答属同类问题；Gou 等[15]提出的 CDST-RAG 将常识知识与动态策略感知引入定向检索增强，表明检索策略的精细化仍是提升生成质量的关键。教育应用方面，Kasneci 等[12]分析了 LLM 在教学中的机遇与风险，Kuhail 等[13]与 Okonkwo 等[14]通过系统综述指出教育类问答系统的主要形态、交互设计范式与评估缺口，普遍认为"答案可追溯"与"拒答边界"是影响其被采纳的核心因素。

工程实现层面，张嘉文等[1]以 FastAPI 提供 RESTful 接口、Vue3 构建交互前端；赵文炜等[2]将 FastAPI 用于 Transformer 辅助的备课系统；郭恒言等[6]验证了 Vue 前后端分离架构在高校业务系统中的可行性；陈荣宝[4]与毛娟[3]则分别从 MySQL 性能优化与 Python+MySQL 快速开发角度说明该技术组合的成熟度，共同构成本课题的可行性依据。

综上，现有研究在 RAG 架构优化与幻觉治理上已较为成熟，但面向校园服务这一"多制度、强约束、需溯源"的垂直场景，仍缺少将向量语义召回与知识图谱主题关联扩展相结合、并把引用校验与拒答判定做成可评测闭环的系统性实现。本课题拟基于 FastAPI 与 Vue 构建该闭环，并以检索命中率、拒答准确率与引用通过率进行量化验证。
