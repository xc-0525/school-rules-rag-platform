## 2. 变更说明

原题目侧重技术路线（RAG + 多智能体）与业务范围（校纪校规），新题目侧重**技术栈（FastAPI + Vue）与业务范围（校园服务）**，两者的关系是：

- **技术栈层面**：后端 FastAPI、前端 Vue3 + Vite，与代码实现完全一致（见 [`architecture-v2.md`](architecture-v2.md)）；
- **业务层面**：由"校纪校规"扩展为"校园服务"，校纪校规仍是**核心语料与最严格的可信问答场景**，同时覆盖图书馆、食堂、校园卡、网络、医疗、心理、就业、场馆等校园服务事项（见 `backend/app/services/ingestion.py` 的主题字典与 `rules/校园服务指南节选.md`）；
- **技术路线不变**：GraphRAG（向量语义召回 + 知识图谱多跳推理）+ 多智能体协作 + 证据约束生成与引用校验，仍是系统的核心机制，只是在题目中不再单列。

## 3. 术语口径约定

1. 对外展示（题目、摘要、PPT、论文封面）统一使用**新题目**；

## 6. 选题报告素材（按新题目措辞，各约 200 字）

**选题目的**

> 校园服务信息与校纪校规涉及学籍、考勤、考试纪律、违纪处分、奖助学金、宿舍、图书馆、食堂、校园卡、医疗与就业等事项，内容分散于多份手册与指南，学生查询依赖翻阅文档或询问他人，效率低易遗漏；通用大模型不掌握本校规定，易编造办理流程与处分标准。本课题拟基于 FastAPI 与 Vue 设计实现一个校园服务智能问答系统，融合向量语义召回与知识图谱多跳推理形成双路证据，并以证据约束生成、引用校验与拒答机制抑制幻觉，完成系统实现与效果评测。

**研究意义**

> 理论上，本课题将向量语义检索与知识图谱推理结合为双路证据，并在生成后加入引用校验与拒答判定，形成"检索—推理—校验"闭环，可为校园服务、规章制度等强约束领域的可信问答与幻觉治理提供可迁移的架构参考；并以显式图编排与可观测轨迹落地多智能体协作，为 Agent 协作可靠性研究提供实证载体。实践上，系统可降低学生获取校园服务与校规信息的成本、减少违纪与处分争议，分担学工教务与后勤部门的重复答疑压力，问答反馈可反哺服务优化与规章修订，架构亦可迁移至其他校园业务场景。
