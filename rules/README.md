# 校规文档目录

## 目录结构

```
rules/
├── wut/        # 真实语料：武昌理工学院官网公开制度（入库用这个）
├── _sample/    # 虚构样例：仅用于跑通链路，禁止用于生产
└── README.md
```

## 入库

```bash
cd backend
python scripts/ingest_rules.py --reset          # 默认就是 rules/wut
```

链路自测（不接真实语料时）：

```bash
python scripts/ingest_rules.py --dir ../rules/_sample --reset
```

## 真实语料怎么来的

`wut/` 下的文件由 `backend/scripts/fetch_rules.py` 从学校官网抓取并清洗生成，
不要手工编辑（重跑会覆盖）。来源 URL、抓取时间、条目数记录在 `wut/_sources.json`。

```bash
cd backend
python scripts/fetch_rules.py            # 用缓存重新清洗
python scripts/fetch_rules.py --force    # 重新下载
```

### 为什么要清洗，不能直接喂网页

项目解析器（`app/services/rules_parser.py`）靠两个标记切块：

- `## 第X章 …` → 章节
- 行首 `第N条` → 条款（检索与图谱的最小单元）

官网正文是 HTML，既没有 `##`，条款编号也常被 `<span>` 拆开、多个编号项被 `&nbsp;`
挤在同一行。直接入库的后果是所有条款落到"正文"章节，引用无法定位到条款，
`verify_grounding` 的条款号核对也会失效。

`fetch_rules.py` 做的处理：

| 问题 | 处理 |
| --- | --- |
| 三种页面模板 | `v_news_content` / `class="article"` / 问答表格，按 class 配平截取正文 |
| 导航、页脚、校对时间 | 按关键词过滤 |
| `第 一 章 总 则`（字间有空格） | 规整为 `第一章 总则` |
| 条款号独占一行 | 与下一行合并 |
| 被 `<span>` 拆散的 `(` `）` | 贴回相邻行 |
| 多个编号项挤在一行 | 按编号切分 |
| 无「第N条」的文档（"一、二、"或"1. 2."） | 顺序映射为 `第1条`、`第2条`，原文编号保留在内容里 |
| 问答表格（图书馆 FAQ） | 一行一转成 `第N条 问：… 答：…` |
| 行内小标题（`作息时间：…`） | 拆成 `##` 章节 |

## 已知的语料缺口

- **同一制度多版本并存**：助学金标准在 `10`、`11` 两份文件中不一致（旧文件引用 2007 年国发文件），
  检索时可能同时召回两个金额。真实使用前建议在 `documents` 上加"生效日期"并在排序时优先取新版。
- **《学生管理规定》不完整**：官网只公开了总则部分（`05`）和第二十五条之后（`06`），
  第十八至二十四条缺失，`06` 的标题已标注"节选"。
- **`21` 为 2020 年版新生入学指南**：作息（23:00 熄灯、周五周六不熄灯、五一至十一通宵供电）
  与住宿费标准来自该页面，时效性需自行确认；正式规定见 `18`。
- **未覆盖**：食堂、校医院、心理健康、就业指导、评奖评优细则（官网无独立制度页）。
